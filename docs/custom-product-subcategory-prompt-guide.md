# 訂製品子分類提示詞 — 四視圖型錄規範（測試版）

**狀態**：`phone_case` 先行測試；通過後再批量更新一百多個 `custom_product_subcategories.prompt`  
**後台**：`public/admin/custom-categories.html`  
**資料表**：`custom_product_subcategories.prompt`（主分類 `custom_product_categories.prompt` 可留空）  
**生圖 API**：`POST /api/generate-product-image` → `buildPromptFromCategoryKeys` + 使用者描述 +（有圖時）參考圖附錄  
**材料／表面特徵政策**：`docs/flux-and-gemini-prompt-policy.md`（**嚴禁**檔名、`material_key` 查表硬編碼；材料句只來自 Gemini `image_semantics_json`）

---

## 1. 架構約定

| 項目 | 約定 |
|------|------|
| 誰寫提示詞 | **子分類**為主；設計頁必選主+子，但主分類 prompt 可空白 |
| 輸出 | **僅一張圖**，內含 **2×2 四格**（不是四張獨立檔、不是四次生圖） |
| 四格內容 | **Split-view 1～4 固定劇本**（實測最穩，勿改成「彈性互補視角」取代） |
| 參考圖四槽 | 原型／材料／配件／圖樣 — **可有可無、可只上部分**；**勿**將四格對應四槽 |
| 參考圖語意 | **擷取產品特徵**套用到型錄四格 — **不是**重繪／複製參考圖畫面；**不得**用參考圖的構圖取代 Split-view |
| 參考圖附錄 | 有上傳時後端自動接 `【參考圖用途 — FLUX 多圖編輯】`；子分類內不必重複 image 編號 |

## 1.1 與你原本提示詞的差異（`phone_case` 對照）

| 項目 | 你原本寫法 | 本文件測試版 |
|------|------------|--------------|
| 品類開頭 + Split-view 1～4 四段劇本 | ✅ 有（核心，**保留**） | ✅ **相同內容**，僅標明對應格位 |
| 四格位置 | `左上、左下、右上、右下` | 測試版已改回與你相同順序（見 §3） |
| 材質舉例 | Split-view 1 內寫「皮革、碳纖維或透明」 | 移到【參考圖】無圖時的 fallback，避免寫死材質 |
| 【輸出格式】 | 僅一句「4個角度圖片平均分配…」 | 明確寫「**僅一張圖**、2×2、四格同一產品」（防模型出四張或拼貼不一致） |
| 【參考圖】專段 | ❌ 無 | ✅ **新增**：有圖／無圖／部分有圖 + **特徵擷取、不重繪、不搶構圖** |
| 風格收尾 | ✅ 有 | ✅ 相同 |

**結論**：四視圖劇本沒改；多的是「一張 2×2」「參考圖怎麼用」兩段，避免 FLUX 把參考圖當成要重畫的成品圖。

## 2. 子分類 prompt 結構（模板）

每個子分類 = **品類專屬段** + **共用段**（下列 【輸出格式】【參考圖】可全站複製）。

```text
（品類專屬）角色 + 該品類結構／物理合理性要求。

【輸出格式 — 必守】
僅輸出一張圖片，內含 2×2 四格型錄；四格須為同一產品、同一配色與圖樣，僅視角不同。
四格平均分配於左上、左下、右上、右下（順序與 Split-view 1～4 對應，勿調換）。

（品類專屬）Split-view 1（左上格）：……
（品類專屬）Split-view 2（左下格）：……
（品類專屬）Split-view 3（右上格）：……
（品類專屬）Split-view 4（右下格）：……

【參考圖 — 擷取特徵，不重繪、不搶構圖】
參考圖用途是提供產品特徵（造型、材質、配件、圖樣），套用到**本提示詞規定的 Split-view 1～4 型錄構圖**上。
禁止把參考圖當成輸出畫面重繪、複製構圖、貼圖或拼貼；禁止用參考圖的拍攝角度、景別、背景取代各格應呈現的視角。
構圖與鏡位以 Split-view 1～4 為準；參考圖只影響「產品長什麼樣」，不影響「每一格該怎麼拍」。
若已上傳參考圖，僅依「實際上傳」的參考與使用者描述擷取特徵（可能零張、或僅部分類別有圖）；
未上傳的參考類型不得憑空補齊。
若完全無參考圖，依本分類與使用者描述推定成品；未描述之材質／表面以該品類常見合理做法處理，四格劇本不變。

（品類專屬，可選）風格收尾：型錄、無文字、無模特等。
```

### 禁止寫法

- 四格各對應一類參考槽（左上=原型、右上=材料…）
- 以參考圖的畫面構圖取代 Split-view（變成重繪參考圖）
- 「彈性選鏡位」**取代** Split-view 1～4 的具體內容
- 要求四類參考都必須上傳
- 輸出四張獨立圖片

## 3. 測試用完整範例：`watches_tech` / `phone_case`（手機殼）

貼入後台子分類 `phone_case` 的「提示詞」欄位，部署與 SQL 無關，改完後台即生效。

```text
你是位專業行動裝置配件與工業設計師，請設計一個高品質的手機背蓋保護殼，結構強調單面扣入式（Snap-on）設計、精確的鏡頭防護構造與按鈕孔位對齊。

【輸出格式 — 必守】僅輸出一張圖片，內含 2×2 四格型錄；四格須為同一支保護殼、同一機型、同一配色與圖樣，僅視角不同。四格平均分配於左上、左下、右上、右下。

Split-view 1（左上格）：背面全景拍攝，展示保護殼整體的比例、背部平面設計與材質質感，呈現簡潔且專業的產品視覺。
Split-view 2（左下格）：45度角側視圖，重點展示鏡頭保護框（Camera lip）的凸起高度、側邊包覆的流線感，以及保護殼與機身接合處的緊密度。
Split-view 3（右上格）：鏡頭孔位細節特寫，極近距離展示鏡頭模組開孔（Lens cutout）的精確對位、邊緣的防磨損倒角細節，以及強化防護圈的結構質感。
Split-view 4（右下格）：側面按鈕與底部孔位特寫，精確展示獨立按鈕（Tactile buttons）的物理構造、側面止滑紋理，以及底部充電孔與揚聲器開孔的精準對齊細節。

【參考圖 — 擷取特徵，不重繪、不搶構圖】參考圖僅供擷取產品特徵（造型、材質、配件、圖樣），套用到上列 Split-view 1～4 的型錄構圖；不得重繪或複製參考圖的畫面、角度與背景來取代各格視角。若已上傳參考圖，僅依實際上傳的參考與使用者描述擷取特徵，未上傳的類型不得憑空補齊；各格仍嚴格依 Split-view 1～4 執行。若完全無參考圖，材質與表面以使用者描述為準（未描述時採該品類常見合理質感，如透明、磨砂、皮革紋、碳纖維紋等），四格劇本不變。

專業產品型錄圖風格，展示於智慧手機機身上或乾淨背景，不要顯示任何文字，不要有人像模特兒，主要展示產品細節，維持保護殼結構與開孔的物理合理性。
```

## 4. 測試清單（`phone_case`）

在設計頁選主分類「鐘錶與科技配件」+ 子分類「手機殼」，各測一輪：

| # | 情境 | 預期 |
|---|------|------|
| 1 | 無參考圖 + 簡短使用者描述 | 單張 2×2，四格同一手機殼，四視圖可辨 |
| 2 | 僅原型參考 | 造型特徵來自參考，但四格仍為 Split-view 1～4 鏡位，**不是**重繪那張原型圖 |
| 3 | 原型 + 材料 | 造型與表面特徵來自參考，四格構圖不變，勿憑空加未上傳的配件 |
| 4 | 僅圖樣參考 | 圖樣套用在四格同一產品上，各格鏡位仍依 Split-view |
| 5 | 有參考 + 使用者指定材質（如「磨砂黑」） | 以描述為準覆寫未指定的部分 |

記錄：seed、是否四格齊全、一致性、是否出現文字／模特。

## 5. 測試通過後：批量改一百多個子分類

1. **匯出現有 prompt**（Supabase）  
   `SELECT category_key, key, name, prompt FROM custom_product_subcategories WHERE is_active ORDER BY category_key, sort_order;`

2. **每個子分類只改兩塊**  
   - 開頭品類句 + Split-view 1～4（各品類不同，保留你已測穩的鏡位劇本風格）  
   - 接上本文件 §2 的【輸出格式】【參考圖】共用段（全文一致）

3. **主分類** `custom_product_categories.prompt` 維持空白或僅一句極短說明，避免與子分類重複。

4. **（可選二期）** 將【輸出格式】【參考圖】改由 `server.js` `composeGeneratePromptWithReferences` 自動附加，子分類只留品類 + Split-view 1～4，減少一百多筆重複維護。

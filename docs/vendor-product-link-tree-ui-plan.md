# 廠商產品關聯樹 — 圖形化介面規劃

> **狀態**：規劃稿（尚未實作）  
> **資料基礎**：既有 `vendor_asset_prototype_links`（主產品 ↔ 材料／配件，一層、多對多）  
> **不在此版**：材料下再掛配件的子樹（需另建主產品）

## 目標

| 對象 | 目標 |
|------|------|
| **訂製者（設計頁）** | 依「選了哪個主產品」一眼看到可搭配的材／配，減少漏選、錯選 |
| **廠商（素材後台）** | 圖形化檢查每個主產品是否缺材料、缺配件、是否有「孤兒」素材從未掛到任何主產品 |

## 核心概念：兩層星狀樹（非無限巢狀）

```
                    [主產品 A]  ← 根（prototype）
                   /    |    \
            [材料 M1] [材料 M2] [配件 P1]   ← 僅一層 children（material | part）
```

- 同一 **材料／配件** 可連到多個主產品（多對多）→ 圖上會出現多條邊或「共用節點」標示。
- **「我的素材分類」** 僅作篩選／著色，不當樹的父子結構。

## 一、廠商端：產品關聯樹工作台

### 1.1 入口與版面

- **位置建議**：`manufacturer-materials.html` 新增頂部 Tab「**產品關聯圖**」（與數位原型／材料／配件上傳並列，或獨立 `/client/vendor-product-tree.html`）。
- **版面（桌面）**：
  - **左 25%**：主產品清單（縮圖 + 標題 + MOQ + 訂製範圍 badge）
  - **中 50%**：**互動圖畫布**（選中主產品為中心的放射狀／橫向 mind-map）
  - **右 25%**：檢查面板 + 未關聯素材池（可拖入）

```text
┌─────────────┬──────────────────────────┬─────────────┐
│ 主產品列表   │     [圖形化關聯樹]        │ 檢查 / 素材池 │
│ ・A 西裝    │        材料M1  配件P1      │ ⚠ 缺配件     │
│ ・B 外套    │           ╲  │  ╱        │ 孤兒：材料X  │
│             │        [主產品 A]          │ [拖入連結]   │
└─────────────┴──────────────────────────┴─────────────┘
```

### 1.2 圖形化互動（廠商）

| 操作 | 行為 |
|------|------|
| 點選主產品 | 畫布以該節點為中心，展開已關聯材／配 |
| 拖曳素材池 → 主產品 | 建立連結（寫入 `vendor_asset_prototype_links`） |
| 拖曳已連結節點 → 空白 | 可選：解除連結（確認對話） |
| 節點上「＋」 | 開啟快速搜尋／篩選（依 kind、我的分類） |
| 雙擊節點 | 開啟既有「編輯」彈窗 |
| 排序 | 主產品下子節點依 `sort_order` 拖曳排序（影響設計端推薦順序） |

**視覺編碼**

- 主產品：大節點、主色邊框
- 材料：綠系 icon／邊框
- 配件：琥珀色 icon／邊框
- **孤兒**（未連到任何主產品）：右側池虛線框 + 數量角標
- **缺漏**（廠商自訂規則，見下）：主產品旁 ⚠ badge

### 1.3 檢查與遺漏提示（廠商 b）

針對**目前選中的主產品**，自動計算：

| 檢查項 | 條件 | 提示 |
|--------|------|------|
| 無任何關聯 | 材+配皆 0 | 「尚未關聯材料或配件」 |
| 僅訂製範圍提示 | `customization_levels` 含 `color_material` 但無材料關聯 | 「訂製範圍含材料，建議關聯至少 1 筆材料」 |
| 同上 | 含 `size_part` 但無配件關聯 | 「建議關聯配件」 |
| 孤兒素材 | 同廠 `material`/`part` 未出現在任何 link | 清單 + 一鍵「掛到目前主產品」 |
| 重複用途 | 可選進階：同主產品下標題相似度（Phase 2） | 弱提示即可 |

**原則**：檢查是**建議**（黃色／橘色），不擋上傳；與設計端「沒關聯才看訂製範圍」一致。

### 1.4 多主產品總覽（Phase 2 可選）

- **縮圖牆模式**：每張主產品卡片下顯示已連結材／配小 chip（最多 N 個 +「+3」）。
- **矩陣模式**：列=主產品、欄=熱門材料，勾選格=有連結（適合 SKU 多的廠商）。

## 二、訂製者端：定製選擇導覽（設計頁）

> 不取代現有「原型／材料／配件」分頁，而是**鎖定主產品後**的輔助導覽。

### 2.1 觸發時機

- 使用者從素材庫選定**廠商數位原型**（原型鎖定）後顯示。

### 2.2 UI 形式（由淺入深）

**Phase 1 — 迷你關聯條（低開發量）**

- 原型分頁下方：橫向 **chip 列**（已關聯材料／配件縮圖 + 標題）
- 點 chip → 切到對應分頁並開素材庫（已篩 `for_prototype_asset_id`）

**Phase 2 — 可摺疊小樹**

```
[主產品 西裝外套]
  ├─ 材料 · 丹寧藍    [選為參考]
  ├─ 材料 · 內裡布    [選為參考]
  └─ 配件 · 金扣      [選為參考]
```

- 已選參考圖的節點打勾；未選但已關聯的節點顯示「建議」樣式（與素材庫「廠商推薦」一致）

**Phase 3 — 精靈式步驟（可選）**

- Step1 原型（必選）→ Step2 建議材料 → Step3 建議配件 → Step4 圖樣（若訂製範圍有）
- 每步只突出**已關聯**項目；其餘仍可在素材庫自行找

### 2.3 與 ⚠️ 規則對齊

- **有關聯**的材料／配件分頁：不顯示訂製範圍 ⚠️（已實作）
- 迷你樹上可標「選填」：未在關聯內的類別仍允許進入，但不主動推

## 三、API（規劃，可復用＋擴充）

| 端點 | 用途 |
|------|------|
| `GET /api/me/vendor-product-link-tree` | 一次回傳 `{ prototypes[], links[], orphans[] }` 供畫布 |
| `PUT /api/me/vendor-assets/:id/prototype-links` | 整批更新單一主產品連結（可從現有 PUT 拆出） |
| `PATCH …/links/reorder` | 僅更新 `sort_order` |
| `GET /api/vendor-assets/prototype-link-summary` | 已有；設計端用 |
| `GET /api/vendor-assets/:prototypeId/link-tree` | 公開：單一主產品子樹（設計頁迷你樹） |

**樹 payload 範例（廠商）**

```json
{
  "prototypes": [{ "id", "title", "image_url", "min_order_quantity", "customization_levels" }],
  "links": [{ "prototype_asset_id", "linked_asset_id", "sort_order" }],
  "assets": [{ "id", "asset_kind", "title", "image_url" }],
  "orphans": ["asset-uuid-..."],
  "checks": [{ "prototype_id", "code": "no_material_link", "severity": "warn" }]
}
```

## 四、技術選型建議

| 方案 | 優點 | 缺點 |
|------|------|------|
| **A. 自繪 SVG + 拖曳** | 無新依賴、風格統一 Bootstrap | 多對多邊線較繁 |
| **B. cytoscape.js** | 圖佈局成熟、縮放平移 | 學習曲線、包體 |
| **C. 簡化「卡片樹」DOM** | 實作快、行動版友好 | 不像傳統樹圖 |

**建議**：廠商端 Phase 1 用 **C（卡片 + 連接線 CSS）** 或 **放射狀 flex**；主產品 >30 再考慮 cytoscape。

## 六、與現有功能的關係

| 現有 | 關聯樹上線後 |
|------|----------------|
| 編輯彈窗勾選 | 保留；樹狀圖為同一 `vendor_asset_prototype_links` 的視覺化 |
| 上傳表單預勾關聯 | 保留 |
| 設計端素材庫推薦排序 | 不變；樹為「導覽」，庫為「完整池」 |
| `vendor_catalog_groups` | 僅篩選，不進樹結構 |
